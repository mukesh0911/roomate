# Testing

The maintained current-workflow entry point is `node scripts/run-workflow-emulators.cjs`. It uses `demo-nestmate-workflows` with Auth 19080, Firestore 18180, Storage 19180, Vite 4186 and callable HTTP 19501. Never run reset-capable suites concurrently against the same demo project.

```powershell
npm.cmd --prefix app run check
npm.cmd --prefix app run lint
npm.cmd --prefix app test -- src --maxWorkers=1
npm.cmd --prefix app run build
npm.cmd --prefix app/functions run check
node --test app/functions/accountJobs.node-test.cjs app/functions/productionReadiness.functions.node-test.cjs app/functions/accountDeletion.node-test.cjs app/functions/discoveryGateway.node-test.cjs app/functions/privacyCompatibility.node-test.cjs
node scripts/run-workflow-emulators.cjs
node scripts/run-workflow-emulators.cjs --regressions
```

The workflow runner also supports `--backend-only`, `--browser-only` and `--browser-security-only`. Install Firebase CLI 15.15.0 and Playwright Chromium, and use Java 21+ for emulators. The loopback callable host runs actual SDK wrappers with emulator Auth verification; its local dispatcher runs actual job logic. Deployed triggers/schedulers and the CLI worker bootstrap require separate staging evidence.

Source unit tests are colocated under `app/src`. Functions tests live under `app/functions`. Dedicated rules tests remain under `app`. `tests/` retains independent-user fixtures, API/integration and historical Playwright suites. Older broad browser suites need route/fixture reconciliation; their presence is not a current pass. Seed/reset helpers must use explicit demo emulator guards.

Keep the small current acceptance evidence set under `docs/workflow-correction`. Logs, screenshots, auth state, progress dumps, build output and Playwright reports are generated output and should not be committed. Deleted screenshot artifacts can be regenerated by the workflow runner. Historical evidence is in the external cleanup backup; do not fabricate a new pass from an old artifact.
