# Private discovery cutover

8 November 2026 - local implementation; release verification in progress

The active landing and Explore readers use `readDiscovery` and `getInteractionContext` callables. The trusted adapter reads existing source records and returns explicit field allowlists. It does not backfill records, rewrite legacy intent, or migrate on login. Anonymous property discovery excludes publisher identity. Member discovery requires an active, completed viewer and an active, completed, explicitly opted-in candidate with an eligible housing intent. Compatibility runs with the shared server-side algorithm; raw quiz answers stay private. Existing participant histories receive only minimal peer identity and pair-specific permission information.

Firestore source records are restricted to their owner and full administrators. Moderators retain report access; their dashboard does not request full private account/listing collections. The old projection collections also reject unknown fields on ordinary reads. The public discovery signal contains a timestamp only and is written by trusted Functions. Readers refresh on that signal and use a fallback interval. Writes still enforce current account, block, quota, consent and listing conditions in rules at commit time; a callable preflight is not authorization for a later write.

Before release, deploy and verify the read endpoints, their shared generated modules, indexes and invalidation triggers in an isolated staging environment. Verify anonymous/member/owner/moderator/admin principals and old-client behavior. Distribute compatible readers and enforce a reviewed minimum version or feature restriction before closing production source reads. Do not preserve broad private reads as a compatibility fallback. A rollback must retain the private boundary. This document is not deployment authorization.

The workflow runner starts a loopback HTTP host on 19501 for the actual exported Firebase `onCall` handlers. It uses the Firebase SDK callable wrapper, real Auth-emulator token verification and real Firestore-emulator data. This isolates the Firebase CLI worker bootstrap, which failed locally. Browser acceptance exercises actual callable HTTP transport through this host; it does not verify the CLI worker or background event delivery. Backend command tests inject the same gateway factory with the real Admin SDK against the isolated database; only the transport is replaced. Those backend checks establish gateway logic plus real client rules, while browser checks separately establish transport integration. Generated matching/intent modules are checked for source drift by the Functions check command.
